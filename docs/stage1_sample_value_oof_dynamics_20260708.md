## Scripts

Initialize the grouped layout:

```powershell
uv run python scripts/stage1_sample_value_experiment_layout_20260708.py
```

Create a checkpoint availability plan without running inference:

```powershell
uv run python scripts/export_stage1_oof_checkpoint_dynamics_20260708.py `
  --job-id node01_folds_00_03 `
  --runs-root C:\path\to\oof_runs `
  --oof-root artifacts\stage1_oof_folds_10fold_20260617 `
  --folds 0-9 `
  --epochs 1-200 `
  --batch 128 `
  --dry-run
```

Export strict OOF checkpoint dynamics:

```powershell
uv run python scripts/export_stage1_oof_checkpoint_dynamics_20260708.py `
  --job-id node01_folds_00_03 `
  --fold-run-map C:\path\to\fold_run_map.csv `
  --runs-root C:\path\to\oof_runs `
  --oof-root artifacts\stage1_oof_folds_10fold_20260617 `
  --folds 0-9 `
  --epochs 1-200 `
  --batch 128 `
  --device 0
```

Formal non-dry-run export requires `--job-id` and exact fold binding through
`--fold-run-map`, unless `--allow-auto-discover` is explicitly used for a
local diagnostic run. The map format is:

```csv
oof_fold,run_dir
0,C:\path\to\fold_00\full_yolo11l_cls_...
1,C:\path\to\fold_01\full_yolo11l_cls_...
```

Duplicate `oof_fold` entries in `--fold-run-map` fail. Duplicate `(oof_fold,
epoch)` entries in `--checkpoint-map` also fail. The binding file must be a
single unambiguous statement of checkpoint provenance.

Use `--resume` only to skip epochs whose CSV and sidecar manifest both validate.
Incomplete CSVs, missing sidecars, duplicate sample IDs, wrong row counts, or
mismatched fold/epoch/checkpoint metadata fail instead of being overwritten
silently.

`resource_log.csv` records memory snapshots both before and after CUDA cleanup:

```text
rss_mb_before_cleanup
cuda_allocated_mb_before_cleanup
cuda_reserved_mb_before_cleanup
rss_mb_after_cleanup
cuda_allocated_mb_after_cleanup
cuda_reserved_mb_after_cleanup
```

Summarize per-epoch predictions into per-sample training dynamics:

```powershell
uv run python scripts/summarize_stage1_oof_checkpoint_dynamics_20260708.py `
  --expected-folds 0-9 `
  --expected-epochs 1-200
```

The summary stage only accepts prediction CSVs with complete sidecar manifests.
It also checks that CSV row metadata agrees with the file path fold/epoch, rejects
duplicate `(fold, epoch)` files across jobs, and requires every sample to have
the exact expected epoch set, not just the same epoch count.

Build grouped replay manifests after a sample-value table has been written:

```powershell
uv run python scripts/build_stage1_sample_value_replay_manifests_20260708.py `
  --sample-value-table artifacts\stage1_sample_value_experiments\experiments\oof_dynamics_gap_value_20260708\02_sample_value_tables\sample_value_table.csv `
  --methods gap_critical `
  --budgets 600,3000,6000
```

The value table must contain one score column per selected method, for example:

```text
gap_critical_score
grad_align_guard_score
```

FP-only methods select only normal samples. Guard methods such as
`grad_align_guard` and `gap_critical_guard` are not generated by default; if
requested, they require an explicit `--defect-guard-budget` so the normal/defect
budget policy is not decided implicitly by the script.

The registry files expose this with `manifest_build_status`:

```text
default_ready
requires_defect_guard_budget
```

## OOF Rule

For fold `k`, predict only fold `k` holdout samples with fold `k` checkpoints.
Do not predict every checkpoint over all 120k samples; that is not strict OOF and would inflate the dynamics table.

Expected full dynamics scale:

```text
10 folds * 200 checkpoints * about 12k holdout samples = about 24M prediction rows
```

The OOF checkpoint archives may use zero-based Ultralytics names:

```text
epoch0.pt ... epoch199.pt
```

In that layout, the exporter maps logical epoch `1..200` to file names
`epoch0.pt..epoch199.pt`.

## Checkpoint Reality Check

If the downloaded archive only contains `best.pt` or `last.pt`, this experiment cannot produce 200-epoch training dynamics from that archive.
Use `--dry-run` first; it writes `01_oof_dynamics/jobs/<job_id>/checkpoint_plan.csv`
and marks missing checkpoints explicitly.
