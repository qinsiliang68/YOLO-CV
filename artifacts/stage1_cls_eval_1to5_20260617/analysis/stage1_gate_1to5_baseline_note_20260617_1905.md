## 1. 本次笔记的目的

这份笔记用于固定当前 Stage-1 CLS Gate 的正式 1:5 基线结论，避免后续讨论时混淆旧评估结果、指标口径和业务含义。

当前课题的第一阶段不是普通分类准确率任务，而是一个高召回 Gate：

1. 先尽量识别并拦下所有疑似缺陷图。
2. 对明显正常图直接放行，不进入后续更重的检测、复核或人工流程。
3. 最危险的错误是“缺陷被判断为正常”，因为它会被放过去，可能丢失病害。
4. “正常被判断为缺陷”虽然是误判，但只是进入第二阶段复核，不会丢掉病害，主要体现为工作量增加。

因此后续论文和实验必须始终围绕这个核心目标：

> 在缺陷召回率约束不降低的前提下，尽量减少正常图进入第二阶段的数量。

当前重点目标可以写成：

> 以 `yolo11l` 为主模型，在保持约 99.5% 缺陷召回的前提下，将正常图误拦数量从 31,747 / 100,000 压低到约 20,000 / 100,000。

如果达到这个目标，正常图放行率将从 68.253% 提升到 80.000%，正常误拦相对下降约 37.0%，论文结果就非常有工程价值。

## 2. 数据和评估协议

本次评估是 1:5 正式评估，不是旧 1:1 评估。

每个评估拆分的数据量：

| split | 缺陷图 | 正常图 | 总数 |
|---|---:|---:|---:|
| `val_cal` | 20,000 | 100,000 | 120,000 |
| `val_op` | 20,000 | 100,000 | 120,000 |
| `test` | 20,000 | 100,000 | 120,000 |

运行设置：

| 项目 | 值 |
|---|---|
| 评估节点 | `192.168.100.18` |
| batch | 128 |
| 目标召回率 | 0.995 |
| 部署缺陷先验 | 0.1 |
| 校准方法 | Platt scaling on `logit(p_defect_raw)` |
| 校准集 | `val_cal` |
| 阈值选择集 | `val_op` |
| 最终报告集 | `test` |

流程必须这样理解：

1. 用 `val_cal` 做概率校准。
2. 按部署缺陷比例 10% 做先验调整，得到 `p_defect_operational`。
3. 用 `val_op` 选择能达到 99.5% 召回的操作阈值。
4. 固定阈值后，只在 `test` 上做最终评估。

也就是说，`test` 没有参与校准，也没有参与选阈值。

## 3. 指标口径固定

为了避免后续混乱，必须固定下面这些口径。

### 3.1 缺陷相关

缺陷总数是 20,000。

| 口径 | 含义 |
|---|---|
| 缺陷判异常 | 缺陷被正确拦下，进入第二阶段 |
| 缺陷判正常 | 漏检，危险错误，缺陷被放过去 |
| 缺陷召回率 | 缺陷判异常 / 20,000 |
| 缺陷漏检率 | 缺陷判正常 / 20,000 |

对于 Gate 任务，缺陷漏检是最需要控制的安全风险。

### 3.2 正常相关

正常总数是 100,000。

| 口径 | 含义 |
|---|---|
| 正常判正常 | 正常图被识别为正常，直接放行，不进入第二阶段 |
| 正常判异常 | 正常图被误认为可疑，进入第二阶段 |
| 正常放行率 | 正常判正常 / 100,000 |
| 正常误拦率 | 正常判异常 / 100,000 |

正常误拦不是安全性错误，但会增加第二阶段负担。

### 3.3 “出来”和“没出来”

后续讨论中，“出来”和“没出来”按下面定义：

| 说法 | 含义 |
|---|---|
| 出来 | 被判为正常，直接放行，不进入第二阶段 |
| 没出来 | 被判为异常，进入第二阶段复核 |

对正常图来说：

```text
正常总数 = 正常判正常 + 正常判异常
100,000 = TN + FP
```

对缺陷图来说：

```text
缺陷总数 = 缺陷判异常 + 缺陷判正常
20,000 = TP + FN
```

正常图的两个数加起来等于 100,000；缺陷图的两个数加起来等于 20,000。不要把正常样本分母和缺陷样本分母混在一起。

### 3.4 部署拦截/复核比例

`weighted_pass_through_rate` 这里实际表达的是按部署先验估计的“进入第二阶段复核比例”。

公式是：

```text
进入第二阶段比例
= 真实缺陷占比 * 缺陷召回率
+ 真实正常占比 * 正常误拦率
```

当前部署先验设定：

```text
真实缺陷占比 = 10%
真实正常占比 = 90%
```

以 `yolo11l` 为例：

```text
缺陷召回率 = 99.525% = 0.99525
正常误拦率 = 31.747% = 0.31747

进入第二阶段比例
= 0.1 * 0.99525 + 0.9 * 0.31747
= 0.385248
= 38.5248%
```

注意，这个不是正常图放行率。正常图放行率是 `68.253%`。

## 5. 单独解释 yolo11l

`yolo11l` 是当前建议主模型。

在 `test` 上：

```text
20,000 张缺陷进去：
- 19,905 张被判断为异常，进入第二阶段
- 95 张被判断为正常，漏检
- 缺陷召回率 = 99.525%
- 缺陷漏检率 = 0.475%

100,000 张正常进去：
- 68,253 张被判断为正常，直接放行
- 31,747 张被判断为异常，进入第二阶段
- 正常放行率 = 68.253%
- 正常误拦率 = 31.747%
```

如果看 test 集实际 120,000 张整体流向：

```text
放过去 = 68,253 正常 + 95 缺陷 = 68,348
进入第二阶段 = 31,747 正常 + 19,905 缺陷 = 51,652
68,348 + 51,652 = 120,000
```

但从业务价值看，更应该关注正常样本部分：

```text
100,000 张正常图里，68,253 张被第一阶段直接筛掉。
```

这说明当前第一阶段已经可以对正常图减轻接近 70% 的后续负担。

## 6. 为什么主模型选 yolo11l

当前只选一个主模型时，建议选 `yolo11l`。

### 6.1 和 yolo11x 比

`yolo11x` 相比 `yolo11l`：

```text
缺陷漏检：93 vs 95
正常误拦：32,913 vs 31,747
```

也就是说，`x` 在 20,000 张缺陷里只少漏 2 张，但在 100,000 张正常里多误拦 1,166 张。考虑到 `x` 的计算成本也更高，这个交换不划算。

直观解释：

1. 当前输入分辨率是 224。
2. Stage-1 是二分类 Gate，不是精细定位或分割。
3. `x` 的大容量在 224 下没有明显释放更多有效信息。
4. 它可能对正常纹理、阴影、管壁结构等背景想得太多，因此误拦更多。

### 6.2 和 yolo11m 比

`yolo11m` 相比 `yolo11l`：

```text
缺陷漏检：99 vs 95
正常误拦：31,660 vs 31,747
```

`m` 少误拦 87 张正常图，但多漏 4 张缺陷。对于 Gate 任务，漏缺陷比多复核正常图更严重。因此综合安全性和减负效果，`l` 更适合做主模型。

### 6.3 和 yolo11s 比

`yolo11s` 缺陷漏检最少：

```text
缺陷漏检：71 / 20,000
```

但代价是正常误拦最多：

```text
正常误拦：36,964 / 100,000
```

它更像“过度保守”的模型，适合作为安全上界对照，但不适合作为主线模型。

### 6.4 结论

后续建议：

| 角色 | 模型 |
|---|---|
| 主实验模型 | `yolo11l` |
| 效率对照 | `yolo11m` |
| 大容量上限对照 | `yolo11x` |
| 小模型容量对照 | `yolo11n` / `yolo11s` |

曲线含义：

1. 阈值越低，越不容易放过缺陷，缺陷召回率越高。
2. 阈值越低，正常图越容易被判为异常，正常误拦率越高。
3. 当前阈值约为 0.003，是因为任务目标是极高召回，不是 0.5 概率分类。
4. 这个阈值是操作分数 `p_defect_operational`，已经经过校准和部署先验调整，不能简单理解成人类直觉里的原始概率。

`yolo11l` 的操作阈值：

```text
0.0035432747
```

这可以用大白话解释为：

> 只要模型觉得有一点疑似缺陷信号，就先拦下来。

## 8. 当前论文机会点

当前 `yolo11l` 的正常误拦仍有：

```text
31,747 / 100,000
```

这说明还有大量正常图被模型当成可疑。这个池子很可能包含很多可挖掘结构：

1. 管壁纹理被误认为裂缝。
2. 阴影、水痕、反光被误认为病害。
3. 正常沉积、边界结构、接口区域被误认为异常。
4. 视频连续帧中同一种正常背景被重复误拦。
5. 某些高置信正常误拦样本揭示了模型学错的背景模式。
6. 某些边界附近正常样本可以帮助模型把判断线压干净。

所以当前不是在一个已经很接近天花板的系统上硬挤 1%，而是在一个还有 31.747% 正常误拦的系统上做数据侧优化。

这对论文很有利。

### 8.1 明确成功目标

以 `yolo11l` 为例，当前：

```text
正常误拦 = 31,747 / 100,000
正常放行 = 68,253 / 100,000
```

如果优化后达到：

```text
正常误拦 = 20,000 / 100,000
正常放行 = 80,000 / 100,000
```

则提升为：

```text
少误拦正常图 = 11,747 张 / 100,000
正常误拦率 = 31.747% -> 20.000%
正常误拦相对下降 = (31.747 - 20.000) / 31.747 = 37.0%
正常放行率 = 68.253% -> 80.000%
```

这个目标既有挑战，又不是遥不可及。只要缺陷漏检不明显上升，这个结果就足够支撑论文主结论。

## 9. 下一阶段实验应围绕什么做

下一阶段不要泛泛追求 accuracy，而要围绕下面目标：

```text
在 yolo11l 上保持约 99.5% 缺陷召回，
把正常误拦从 31,747 尽量压低，
理想目标是接近或低于 20,000。
```

优先实验方向：

| 方向 | 目的 |
|---|---|
| 困难正常样本加权 | 直接压低正常误拦 |
| 高置信正常误拦样本加权 | 纠正模型学错的正常背景 |
| 边界附近正常样本加权 | 清理判断阈值附近的混淆样本 |
| 抱团正常误拦样本加权 | 利用重复出现的可学习误差模式 |
| 孤立极端误拦样本审计 | 防止把噪声、异常图、脏数据当成高价值样本 |
| 重复帧降权 | 避免连续视频帧重复放大同一信息 |
| 疑似噪声降权 | 避免极端错误样本带偏模型 |

后续样本价值函数应优先服务于：

```text
减少正常误拦，而不是单纯提高训练准确率。
```

## 11. 后续写论文时可以直接使用的表述

推荐表述：

> 在最终 1:5 测试集上，`yolo11l` 在 99.525% 缺陷召回率下，可将 100,000 张正常图中的 68,253 张直接判定为正常并放行，正常样本第一阶段减负率达到 68.253%。与此同时，缺陷漏检数为 95 / 20,000，漏检率为 0.475%。这说明 Stage-1 Gate 已经能够在极高召回约束下显著降低后续复核负担，但仍有 31,747 / 100,000 的正常图被误拦，构成后续数据侧优化的主要空间。

推荐主目标表述：

> 后续样本价值优化的核心目标是在保持约 99.5% 缺陷召回率的条件下，将正常误拦数从 31,747 / 100,000 降至约 20,000 / 100,000，从而将正常样本放行率由 68.253% 提升至约 80.000%。

推荐主模型选择表述：

> 综合缺陷安全性、正常减负能力和计算成本，后续主实验采用 `yolo11l` 作为主模型。相比 `yolo11x`，`yolo11l` 仅多漏 2 / 20,000 个缺陷，却少误拦 1,166 / 100,000 个正常样本；相比 `yolo11m`，`yolo11l` 仅多误拦 87 / 100,000 个正常样本，却少漏 4 / 20,000 个缺陷。因此 `yolo11l` 是当前最合理的单一主模型选择。
